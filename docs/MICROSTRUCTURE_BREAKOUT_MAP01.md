# Microstructure Breakout Map 01 — frozen before first run

## Purpose

This is a separate historical exploratory research line. It does not modify, rescue, score, filter, or consume the sealed evidence of Exp27 or Decision Calibration, and it is not a continuation of Replay02.

Research question:

```text
At a causally-known M5/M15 support or resistance:

ATTACK
  -> do spread / quote migration / tick-intensity changes predict a FULL-QUOTE BREAK?

FULL-QUOTE BREAK
  -> does the same microstructure fingerprint predict continuation during the next 60 seconds,
     including +50 / +100 / +200 / +300 MT5 points before full-quote recapture?
```

The initial map deliberately does **not** use candle color, candle body direction, discretionary chart marking, fitted spread thresholds, volume/Last tape, Replay02 signal, or outcome-selected subgroups.

## Data contract

- Symbol: `GOLD`.
- Broker execution feed: MetaTrader5 `COPY_TICKS_ALL` from the connected ActivTrades account.
- Tick fields used: `time_msc`, `bid`, `ask`, `flags` only; directional calculations are derived directly from BID/ASK changes.
- `last`, `volume`, `volume_real`, `TICK_FLAG_BUY`, and `TICK_FLAG_SELL` are not used because the observed GOLD feed provides them as zero.
- Price precision observed before freeze: `digits=2`, `point=0.01`.
- Historical mapping window for Map01: `2026-02-01 00:00:00 BRT` through `2026-08-12 23:59:59 BRT`.
- Intraday event window: `09:00:00 <= BRT attack time < 18:00:00`.
- The tick pull includes pre/post buffer outside the event window so 30-second causal baselines and 60-second outcomes remain observable.
- Missing broker tick history is reported as missing coverage; it is not imputed.

Observed feed capability before freeze (capability probe only, not outcome evidence):

Historical tick retention was also observed in February, May, and August 2026, so the Map01 window is selected for broker-data availability rather than outcome selection.

## Causal structural levels

Only M5 and M15 confirmed swing levels are used.

Map01 reuses the TradingAgent causal pivot columns already produced by `Base_Dados.py`:

```text
swing_high_confirmed
swing_low_confirmed
confirmed_swing_high_price
confirmed_swing_low_price
```

Those columns are generated by the existing `confirmed_pivots_block` with the configured 2-left / 2-right confirmation rule. The event is timestamped on the confirmation row, not retrospectively on the pivot-source row.

Level type:

```text
SWING_HIGH -> RESISTANCE -> direction +1 / UP
SWING_LOW  -> SUPPORT    -> direction -1 / DOWN
```

Only the **first observed attack of each confirmed level** is included in Map01. A level already beyond the relevant side of the quote when it becomes observable, or found already crossed at the beginning of a new 09:00 BRT data window, is treated as stale/outside-window crossed and is not reintroduced.

No candle color is part of level creation, attack definition, feature construction, or labels.

## Tick event definitions

For resistance `L`:

```text
ATTACK_UP = first tick with ASK >= L while the level is active
FULL_QUOTE_BREAK_UP = first tick at/after attack with BID > L
FULL_QUOTE_RECAPTURE_UP = first tick after break with ASK < L
```

For support `L`:

```text
ATTACK_DOWN = first tick with BID <= L while the level is active
FULL_QUOTE_BREAK_DOWN = first tick at/after attack with ASK < L
FULL_QUOTE_RECAPTURE_DOWN = first tick after break with BID > L
```

A break can occur on the same tick as the attack. No persistence requirement is added in Map01.

## Pre-attack microstructure features

All features are causal and use ticks at or before attack `t0`.

Core quote state:

```text
mid = (bid + ask) / 2
spread = ask - bid
spread_baseline = median spread in the previous 30 seconds
spread_ratio = spread(t0) / spread_baseline
spread_delta_250ms
spread_delta_1s
spread_delta_5s
```

Tick intensity:

```text
tick_rate_250ms
tick_rate_1s
tick_rate_5s
tick_rate_baseline_30s
tick_rate_ratio_250ms
tick_rate_ratio_1s
tick_rate_ratio_5s
tick_accel_1s_vs_prev4s
```

Directional quote migration, signed so positive always means movement in the breakout direction:

```text
signed_mid_impulse_250ms / 1s / 5s
signed_bid_impulse_250ms / 1s / 5s
signed_ask_impulse_250ms / 1s / 5s
directional_mid_update_fraction_1s
both_quote_change_fraction_1s
```

`spread_ratio > 1.0` is reported as the pre-specified coarse contrast **spread expanded vs did not expand** because that is the motivating hypothesis. No alternative spread cutoff is fitted in Map01.

Continuous variables remain continuous in the event ledger. Quintile maps are descriptive only and cannot be promoted as thresholds from Map01.

## Question A — Attack -> Break labels

From attack `t0`, report whether a full-quote break occurs within:

```text
1s / 2s / 5s / 15s / 30s / 60s
```

Also record exact `time_to_break_ms` when a break occurs within 60 seconds.

Primary coarse descriptive contrast:

```text
P(FULL_QUOTE_BREAK <= 60s | spread_ratio > 1)
-
P(FULL_QUOTE_BREAK <= 60s | spread_ratio <= 1)
```

This contrast is diagnostic in Map01, not a formal promotion gate.

## Question B — Break -> Continuation labels

For attacks that produce a full-quote break within 60 seconds, reset the continuation origin to the `break_mid` at the exact break tick.

Signed continuation horizons:

```text
1s / 2s / 5s / 10s / 15s / 30s / 60s
```

Report signed return in MT5 points, MFE and MAE during the 60-second post-break window.

With `point=0.01`, fixed continuation distances are:

```text
50 points  = 0.50 GOLD
100 points = 1.00 GOLD
200 points = 2.00 GOLD
300 points = 3.00 GOLD
```

For each distance, label whether the signed MID reaches that distance from `break_mid` **before** full-quote recapture and within 60 seconds.

Primary motivating continuation diagnostic:

```text
P(+200 points before recapture | spread_ratio > 1)
-
P(+200 points before recapture | spread_ratio <= 1)
```

Again, this is descriptive in Map01, not a formal promotion gate.

## Uncertainty and maps

Map01 reports:

- event counts by timeframe and side;
- broker tick-coverage diagnostics;
- Attack->Break rates at all frozen horizons;
- Break->Continuation hit rates for 50/100/200/300 points;
- coarse `spread_ratio > 1` vs `<=1` contrasts;
- whole-BRT-attack-day bootstrap CI95 for the two primary coarse contrasts, `N=5000`, seed `2026081704`;
- descriptive quintile maps for `spread_ratio`, `tick_rate_ratio_1s`, `tick_accel_1s_vs_prev4s`, and `signed_mid_impulse_1s`;
- a descriptive 2D quintile grid of `spread_ratio x tick_rate_ratio_1s` for BREAK<=60s and, among broken events, +200-before-recapture.

No threshold is selected from the best quintile/cell in Map01. Any candidate fingerprint discovered here requires a separately frozen Map02 before it can be judged as a hypothesis.

## Anti-leakage / anti-rescue

Map01 must not:

- use red/green candle color;
- mark support/resistance retrospectively by eye;
- use future bars to define a level before its confirmation row;
- use Last/volume/BUY/SELL data that are zero in the broker feed;
- optimize spread threshold, tick-rate threshold, horizon, target distance, timeframe, side, hour, weekday, or combination after seeing results and call it a Map01 PASS;
- drop failed/slow breaks from the ATTACK universe;
- count repeated attacks of the same level as independent Map01 events;
- merge this evidence into Exp27 or Decision Calibration;
- promote runtime behavior from Map01.

## Map01 status semantics

Map01 is a **mapping / discovery experiment** and therefore has no formal PASS/FAIL gate.

Its valid terminal state is:

```text

```
